# Native media module

`./native/build.sh [arm64|x86_64]` builds a macOS 15+ library at `native/build/libscreenrec.dylib`. The install name is `@rpath/libscreenrec.dylib`; bundle it in `Contents/Frameworks`. Builds replace the output atomically, so a running process can retain its previous mapped library. The app needs screen recording, camera, microphone usage descriptions/permissions and audio/video capture entitlements when sandboxed.

Two C symbols are exported:

```c
void screenrec_attach_window(void *nsWindow);
void screenrec_command(const char *json, void (*callback)(const char *json));
```

Requests are `{id,method,params}`. Every accepted request calls the callback exactly once with `{id,result}` or `{id,error:{code,message}}`. The callback JSON pointer is borrowed for the duration of the callback: the caller must copy it. The incoming pointer is copied immediately. AppKit and AVPlayer state changes run on the main actor; sample writing and compositing run on dedicated serial queues. `screenrec_attach_window` receives the host NSWindow pointer, which the app must keep alive.

Native methods match the server bridge:

- `capabilities`, `permissions.request {kind:screen|camera|microphone|input}`. Listing never prompts. Explicit screen or input requests open their respective System Settings panes if access remains ungranted and return the actual permission state. `input` means Input Monitoring; cursor position and clicks are polled independently of this optional permission. With existing Input Monitoring access, a listen-only `CGEventTap` samples coarse typing activity at most once per 600ms; only time and prior pointer focus are stored. It does not require Accessibility permission ([Apple DTS guidance](https://developer.apple.com/forums/thread/811443)). Key text, keycodes and other event contents are never read or saved. Capture continues without typing activity when permission is absent or the optional tap cannot be installed.
- `recording.start {projectId,projectDir,settings}`, `pause`, `resume`, `stop`, `status`, `camera {visible?,enabled?,shape?}`. Camera `visible` controls the floating preview; `enabled:false` also stops camera hardware. Status includes `cameraRunning`, the actual AVFoundation capture session state. Camera active ranges describe recoverable source footage; hiding a preview preserves recording. Region coordinates use source logical points.
- `preview.load {project,projectDir}`, `bounds {x,y,width,height}`, `seek {timeMs}`, `play`, `pause`, `status`, `frame {project,projectDir,timeMs,path}`. Bounds use top-left CSS coordinates in the window content; zero dimensions hide the native view. Thumbnails retain the selected canvas or source aspect ratio with a 960px longest edge. Player status is `{timeMs,playing}`.
- `export.start {project,projectDir,path,width,height,jobId,format?,gifFps?,loop?}` returns `{started:true,jobId}`. Poll `export.status {jobId}` for `{status,progress,path,error?}`; use `export.cancel {jobId}`. Output is MP4/H.264/AAC or an ImageIO GIF (15/20/25/30 fps, at most 60 seconds and 1280px per dimension, without audio), and is moved into place without overwrite after successful rendering. Existing destinations produce `file_exists`.
- `media.filmstrip {path,image?,startMs,endMs}` returns eight source-time JPEG frame samples (192×108 maximum for video). `media.waveform {path,startMs,endMs}` returns 256 real RMS bins, or an empty array when no audio track exists. The desktop service resolves project paths, caches immutable source/range results and serializes sampling; UI requests are debounced and limited to visible timeline clips. Reorder and speed changes reuse the same source samples.
- `audio.inspect {path}` validates an imported audio track and returns `{durationMs}`.
- `audio.analyze {project,projectDir}` returns microphone/system source-time 20ms RMS dB bins. `audio.prepare {projectDir,source,path}` creates mono 16kHz PCM WAV with track startup gaps preserved. `media.inspect {path}` returns duration, dimensions, frame rate and audio presence.
- `project.trash {path}` uses macOS Trash. `keychain.get|set|delete {provider,key?}` stores provider keys in the macOS Keychain.

Recordings contain separate `media/screen.mov`, optional camera/microphone/system files, and cursor JSON. Every source is normalized to the first captured screen frame using native clocks; pause time is removed identically across tracks. Floating recorder windows are excluded from raw screen frames. Window capture uses an auxiliary audio-only display stream when system audio is requested, so unrelated application audio is included too. Camera hardware gaps stay invisible even if AVFoundation holds the previous decoded frame.

Cursor capture holds at most 60 samples, then appends them to JSON. A recovery metadata snapshot is saved every five seconds; media uses one initial one-second fragment and subsequent ten-second fragments. Recovery must inspect readable media duration and clamp stale snapshot duration to it. Cursor loading tolerates an unclosed array or an incomplete last event. Originals are never rewritten by edits. Camera masks, cursor, zoom easing, text/images and captions use one Core Image compositor for deterministic preview, thumbnails and export. No FFmpeg or browser media renderer is needed.

Timeline segments retain array order and may repeat or revisit any source interval. Optional `assetId` selects an imported `video` or `image`; an absent ID selects the original recording. Inserted videos retain their orientation and embedded audio, controlled by system volume. Still images use their range as display duration (up to 60 seconds before speed adjustment). A stretched original frame supplies AVFoundation timing for stills, including image-only timelines and image tails, and the compositor replaces it entirely with the still. Original recordings remain in the project. Camera, cursor, zoom, overlays and captions only apply to original-recording segments; the native source-time lookup returns `-1` on inserted media. Canvas styling applies to every segment. Optional timeline segment `speed` retimes the selected video and its audio together from 0.25× to 8×; original segments include their camera, microphone and system audio. All effects continue to use source timestamps; AVFoundation's spectral time-pitch algorithm preserves pitch in preview and export. Audio composition tracks are reused by source and constant speed to avoid AVFoundation's mixed-rate processor truncation. Optional `edits.canvas` adds source/16:9/9:16/1:1/4:5 layouts, solid/gradient/original procedural wallpaper/imported-image backgrounds, background blur, padding, rounded screen corners, shadows and minimal/browser chrome. Chrome titles use an explicit label or the recorded window title; no browser URL is inspected. Camera, overlays and captions stay anchored to the output canvas. Projects without canvas settings retain their undecorated source view, including the correct source aspect ratio in thumbnails.

Zoom motion may be `gentle` or `snappy`; the default 400ms lead allows either transition to finish before the action. Following starts after a short hold, extended past the first click/drag/typing marker when present. Follow paths are derived once from cursor metadata, so cuts, speed changes and repeated seeks produce the same view. The input tap and its run-loop source are invalidated when recording stops; timeout recovery rechecks permission before re-enabling the tap. Portrait export supports 2160×3840 with the same compositor.

Run `./native/check.sh` for synthetic source/timeline/mask/visibility/seek parity, all-track speeds and decoded audio pitch, canvas backgrounds/styles/aspects, 1080p/4K/portrait export, preview/export color parity, audio bins, WAV and path/recovery checks. It writes inspection artifacts to a new temporary directory. `./native/check.sh --capture-check` opens a separate synthetic AppKit test window and records only it for a few seconds with microphone/system audio and pause/resume; existing screen and microphone permissions are required. It never requests camera permission. `native/build/native-check --rpc` accepts newline JSON for diagnostics.

Verified here: native ARM64 build, synthetic 4K/1080p media pipeline, short real screen/microphone/system capture and an initial real-camera recording. Still requires physical-device acceptance testing: the complete camera hardware off/on and gap-export sequence, unplug/reconnect, Intel Macs, extended 4K recording/synchronization, display rearrangement, and crash/disk-full scenarios. Camera sample and SCK clocks are aligned in code; the short recording does not establish long-session synchronization.

Editor additions share the preview/export compositor: arrows, regional blur, opaque covers applied above other layers, cursor blur/bounce/sway/loop and camera mirror/corners/shadow/zoom response. Imported audio clips occupy separate composition tracks anchored to output time; video retiming does not retime them. See [editor features](../docs/editor-features.md) for schemas and limits. Synthetic checks also decode imported audio, inspect privacy-cover pixels and GIF frames, and verify cursor/camera effects.

Adjacent zoom pieces with identical visual settings use one rendering envelope, so splitting does not restart zoom easing, cursor following or camera shrink. Project IDs remain separate for editing; changing either piece's settings separates its rendering. Native checks compare exact frames before, at and after a split and cover focus-cache refresh and overlapping-effect priority.
